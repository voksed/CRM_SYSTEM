# CRM System

[English](README.md) · **Русский**

**Опенсорсная CRM для рынка СНГ на Django + ванильном JS/CSS** — контакты, канбан-воронка сделок, задачи, биллинг, ролевой доступ, движок автоматизаций, интеграция с Telegram и полный аудит-лог. Без фронтенд-фреймворков, без сборки, без лишнего.

## Зачем это нужно

Большинство туториалов по CRM заканчиваются на «добавьте контакт». Этот проект идёт дальше: лиды двигаются по настоящей воронке продаж, менеджеры видят только свои данные, действия записываются в лог, а движок правил реагирует на события в воронке — и всё это на серверном рендеринге Django и обычном JavaScript, без React/Vue и без сборщиков.

## Возможности

- **Контакты и лиды** — источник, статус, теги, ответственный менеджер, полная лента коммуникаций по каждому контакту
- **Канбан-воронка сделок** — перетаскивание между этапами на нативном HTML5 Drag & Drop API, без JS-библиотек
- **Задачи** — сроки, подсветка просроченных, автоматическое создание follow-up-задач правилами автоматизации
- **Биллинг** — счета с публичными ссылками на оплату, ручное внесение платежей, текущий баланс по каждой сделке
- **Ролевой доступ** — Владелец видит всё и всем управляет; Менеджеры ограничены своими контактами, сделками и задачами на уровне запросов к базе, а не просто скрытием в интерфейсе
- **Движок автоматизаций** — настраиваемые триггеры (сменился этап, поступил платёж, нет активности N дней) → действия (создать задачу, перевести на другой этап, записать событие)
- **Интеграция с Telegram** — настоящее подключение бота на [aiogram](https://github.com/aiogram/aiogram); входящие сообщения из неизвестных чатов автоматически создают новый лид (в комплекте и вебхук, и команда для long-polling), настраивается на странице настроек прямо в приложении — админка не нужна
- **Аудит-лог** — каждый вход в систему (успешный и неудачный, с IP), каждое создание, изменение, удаление и перемещение — с указанием, кто и когда это сделал
- **Светлая и тёмная тема**, генерация надёжных паролей для новых аккаунтов, защита логина от перебора

## Стек технологий

| Слой | Решение |
| --- | --- |
| Бэкенд | Django 5.2, Django REST Framework |
| Фронтенд | Ванильный JavaScript (`fetch`, нативный Drag & Drop), обычный CSS с кастомными свойствами для тем |
| База данных | По умолчанию SQLite — для продакшена замените настройку `DATABASES` на Postgres/MySQL |
| Аутентификация | Встроенная система auth Django + собственная модель `User`, вход с ограничением частоты попыток |
| Сообщения | [aiogram](https://github.com/aiogram/aiogram) 3.x (асинхронный), подключён к синхронным вьюхам и командам Django через `asgiref` |
| Конфигурация | `python-dotenv` — секреты и настройки окружения живут в локальном `.env` и никогда не попадают в репозиторий |

## Быстрый старт

### Требования
- Python 3.11+

### Установка

```bash
git clone https://github.com/voksed/CRM_SYSTEM.git
cd CRM_SYSTEM

python -m venv venv
venv\Scripts\activate          # Windows
# source venv/bin/activate     # macOS/Linux

pip install -r requirements.txt
```

Создайте файл `.env` в корне проекта (в репозиторий он не попадёт — прописан в `.gitignore`):

```bash
DJANGO_SECRET_KEY=change-me-to-a-long-random-string
DJANGO_DEBUG=True
DJANGO_ALLOWED_HOSTS=127.0.0.1,localhost
TELEGRAM_BOT_TOKEN=
```

Сгенерировать настоящий секретный ключ можно так: `python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"`.

```bash
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Откройте **http://127.0.0.1:8000/** и войдите под только что созданным суперпользователем — организация и воронка продаж по умолчанию создадутся автоматически при первом входе.

### Интеграция с Telegram (опционально)

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите его токен.
2. В приложении откройте раздел **Telegram** в боковом меню (доступен только Владельцу) и вставьте токен — он сразу проверяется через Telegram API, а после подключения показывается имя бота. (По желанию можно заранее задать `TELEGRAM_BOT_TOKEN` в `.env`, тогда поле будет заполнено.)
3. Начните принимать сообщения:

   ```bash
   python manage.py run_telegram_bot
   ```

   Запустится процесс long-polling на aiogram, который слушает сообщения, пока вы его не остановите (`Ctrl+C`). Сообщения из чатов, ещё не связанных с контактом, автоматически создают новый лид. Для продакшена используйте вебхук-эндпоинт (`channels_app.views.telegram_webhook`) вместо long-polling.

## Структура проекта

```
accounts/       организации, пользователи, роли, права доступа
contacts/       лиды и контакты, теги
deals/          воронки, этапы, сделки
tasks/          управление задачами
billing/        счета и платежи
automation/     движок правил (триггеры → действия)
channels_app/   каналы связи (Telegram) + лента коммуникаций
audit/          аудит-лог (кто, что, когда и откуда)
config/         настройки Django-проекта и корневые URL
```
